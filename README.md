# peep

**Инспектор памяти живых процессов Windows**

`peep` – read-only инструмент для анализа виртуальной памяти x64-процессов Windows, строит карту адресного пространства, парсит PE-заголовки загруженных модулей прямо из памяти, флагует подозрительные исполняемые регионы через эвристику энтропии Шеннона

## Для чего можно использовать

`peep` показывает артефакты, которые оставляют инжекторы и лоадеры: 
исполняемые PRIVATE-регионы, PE-заголовки внутри приватных аллокаций, стертые заголовки, высокоэнтропийные регионы.

Проект продолжает [DictOS](https://github.com/hgyc/DictOS). Работает с живым процессом через `ReadProcessMemory`, где образ отличается от файла, секции замаплены по VA, применены релокации, заполнен IAT

## Статус 

- [x] Поиск процесса по имени / PID, открытие с минимальными правами
- [x] Карта памяти через `VirtualQueryEx`
- [ ] Парсинг PE-заголовков и таблицы секций из памяти
- [ ] Энтропия Шеннона для исполняемых регионов без PE
- [ ] Эвристические флаги 

## Возможности (MVP)

- Поиск процесса по точному имени образа (case-insensitive) или PID (`CreateToolhelp32Snapshot`)
- Полная карта committed-памяти через `VirtualQueryEx`: база, размер, тип (`IMAGE` / `PRIVATE` / `MAPPED`), флаги защиты – включая `PAGE_EXECUTE_WRITECOPY`; регионы `PAGE_GUARD` и `PAGE_NOACCESS` пропускаются и никогда не читаются
- Парсинг PE из памяти: валидация DOS/NT сигнатур, поддержка PE32+ (`0x20b`), точка входа, таблица секций (имя, VA, виртуальный размер, характеристики); PE32 детектируется и сообщается как неподдерживаемый
- Энтропия Шеннона для исполняемых регионов без валидного PE; `> 7.0` флагается как эвристика packed/shellcode
- Read-only по дизайну: запрашиваются только `PROCESS_QUERY_INFORMATION | PROCESS_VM_READ`; никаких записей, инжектов, создания потоков
- C++17: RAII-обертка `HANDLE` (move-only, rule of five), типизированное чтение удаленной памяти `read_remote<T>` с возвратом `std::optional`, каждое поле проверяется по фактически прочитанным байтам
